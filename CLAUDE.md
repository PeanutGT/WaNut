# WaNut

Windows desktop app (C# / .NET 10, WPF) that lets casual players create and run a Minecraft: Java Edition server in a few clicks.

## Rules
- Follow every rule in @docs/CONVENTIONS.md.
- Never add AI co-author lines or AI attribution (Claude, Gemini or other) to commits or PRs.
- Never push directly to `main`; work on a branch and open a PR for Peanut to review.
- Before starting a task, check the available skills and use the one that fits.
- Build: `dotnet build` · Test: `dotnet test` · Format: `dotnet format`

## Reading the spec
`docs/blueprint.md` (about 30 KB) is the product spec and decision log. It is not loaded automatically; read only the sections your task touches, e.g. `grep -n '^#' docs/blueprint.md` and then that section. The code is the source of truth; read every file you change.
- Decisions: "Decisions Log" · Java, jars, JVM flags: section 1 · Connect/firewall: 2 · process control: 3
- Tabs and what is always visible / More settings / Advanced mode: 4b
- Backups, world import/export, delete server, change type or version: 5 · Build order and next step: 7
- Anything visual (colors, pixel art, spacing, text sizes, motion, in-window panels): `docs/design.md`; rollout order: `docs/design-rollout.md`

## Code map
- `src/WaNut.Core/` logic only, never references WPF. One folder per module: Backups, Collections (`ListSync` updates a list in place, only where it changed), Crashes (crash cause from console + crash report, fix helpers), Downloads, Hosting (`IServerRuntime` decides where a server runs: `LocalServerRuntime` = java.exe on this PC; `IRunningServer` is one run, `RunningServerBase` shares log parsing and players; process, log parser, Job Object), Http, Instances, Java, Jvm, Modpacks (.mrpack and CurseForge server pack read + install), Mods (Modrinth; `ModJars` reads mod ids from jars), Network (adapters, firewall, UPnP port forwarding, `ServerPorts` picks a free port per server), Notifications (Discord webhook), Packs (`PackLibrary`: Modrinth data packs in the world's `datapacks` folder and the server resource pack in server.properties), Players, Profiling (spark profiler install + report link), Properties, Remote (the user's own Linux VPS over SSH.NET: `VpsProfile` in config.json, `SecretStore` DPAPI secrets, `VpsConnector` host key check + sign-in, `HostProbe` (also reads `VpsProvider` from DMI); `Firewall/HostFirewall` reads the VPS's own firewall (iptables, ufw, firewalld) and builds the add-only command that opens a server port; `Reach/VpsReachability` checks from this PC that friends can reach host:port (Connect tab); `Sync/FolderSync` makes a server folder match the VPS copy over SFTP by size + time, `SyncRules` says what never syncs; `SshUploadCopy`/`SshDownloadCopy` send files as one gzip tar stream (stage folder + size check on upload), `RemoteListing` lists with one `find`, both only when the VPS has GNU tar/find, else per-file SFTP; `VpsSettingsSync` reads and writes only `server.properties` while the files stay on the VPS; `Files/` is the VPS side of `Storage/IServerFileSystem`: `VpsSession` (shared SSH + SFTP channels, SFTP calls take turns, 15 s keepalive, one reconnect and retry on a dropped connection, own SFTP connection per upload/download), `RemoteVpsAdapter` (opens by real path; list with one `find`, delete and tar as one sh command each, edits via `SftpSyncTree` atomic write), `WorkspaceRootGuard` (refuses /, system trees, /home/x, /var/x, the user's home and above; the delete command also needs server.properties, eula.txt or libraries/ and refuses paths through links out of the folder), `RemoteFileCommands`; `Run/` runs a server there: `RemoteServerRuntime` + `RemoteServer` (runner sh script with FIFO input and a console log, systemd service when the account has password-less sudo, tail over SSH, reconnects), `RemoteJava` (Temurin on the VPS), `VpsLaunchPlanner` (checks the VPS RAM against the server memory, upload before start, download after stop, `CheckRunAsync` + `VpsRun` find a run left going when WaNut closed; `RemoteServer` follows it again with a runner pid, `Detach` lets go on close), `RemoteShell` quoting), Settings, Sharing (invite card), Steps (`StepFlow` + `StepLists`: the loading strip's steps for create, start, stop, backup; `ServerLogParser.Phase` reads world loading/saving lines), Updates (Velopack), Versions (Mojang, Paper, Fabric, Forge, NeoForge; `ForgeInstallerRunner` runs the loader installers), Workspace (the Files tab's logic over any `IServerFileSystem`: `FolderTree` opens folders lazily, `WorkspaceBrowser` adds up size per category and opens/saves text files, refusing to overwrite a change made meanwhile; `FileOrganizer` is the clean-up: `EvaluateAsync` dry run (old logs, disabled mods, backups past `BackupRules` via `BackupStore.Expired`, loose world copies packed into backups/) then `ExecutePlanAsync` on the checked items, never the world), Worlds (import/export, `Nbt/`). `LauncherPaths.cs` resolves data folders.
- `src/WaNut.Core/Hotplug/` datapack hot-plug on a VPS server (phase 1 only, no UI yet): `HotplugWorkspaceInitializer` makes `.nut-staging/datapacks` and `.nut-backup/datapacks` (under the world folder instead when `df -P` says the mounts differ, so renames stay atomic) through `IRemoteCommandRunner` (`VpsSession` implements it); `HotplugLock` is the `.lock` file (pid, machine, VPS-clock time, owner; stale after 10 min unless refreshed); `HotplugBackups` names backups with a UTC stamp and prunes to the newest 5 per datapack; `Readiness/ReadinessGate` waits on an `IReadinessSource` (`LocalReadinessSource`, `ServerFolderReadinessSource` for local or VPS folders) until size/time are stable two looks in a row, files open exclusively, the debounce window (3 s) is quiet, and a `.ready` or `manifest.json` flag exists when asked; times out after 5 min. `SyncRules` never syncs the two staging folders.
- Version-dependent rules (properties vs game rules, world layout, presets) live in `src/WaNut.Core/Settings/GameFeatures.cs`.
- `src/WaNut.Bridge/` headless Minecraft <-> Discord bridge (console exe, Windows + Linux, `dotnet publish -r win-x64|linux-x64|linux-arm64` gives one trimmed self-contained file): `GameLog/` (`LogTailReader` follows latest.log across restarts, `MinecraftLogParser` chat/join/leave/death/advancement), `Rcon/` (`RconClient`, `RconLink` reconnects with backoff, `Tellraw` builds the JSON with Utf8JsonWriter), `Discord/` (`DiscordOutbox` 300 ms batching + 429 waits, `DiscordHttpPoster` webhook or bot channel, `Gateway/DiscordGateway` own Gateway client (identify, heartbeat, resume), `DiscordRest` + `SlashCommandDefinitions` guild slash commands /list and /cmd), `Relay/` (`BridgeRelay` filters and routing, `InboundRouter` loop guard and slash commands, `BridgeTexts` English / zh-TW by `language`), `BridgeEngine` wires it, `StatusPipeServer` answers status/stop on a per-server named pipe (`--status`/`--stop <id>`). Reads `bridge.config.json` (WaNut.Core/Bridge, generated JSON; `BridgeSecrets` "dpapi:" fields decrypted on Windows). Tests in `tests/WaNut.Bridge.Tests/`. Deployers in `WaNut.Core/Bridge`: `IBridgeDeployer` + `BridgeDeployerFactory`, `BridgeDeployRun` (steps + rollback), `DiscordCheck` (token, channel permissions), `BridgeBinarySource` (bundled `bridge\<rid>\` copied to %APPDATA%), `Local/LocalBridgeDeployer` (background process or sign-in task via `WindowsBridgeHost`), `Vps/SshVpsBridgeDeployer` + `VpsBridgeScripts` (systemd service in /opt/wanut-bridge with password-less sudo, else a setsid restart loop in ~/wanut/bridge; firewall check for the RCON port; remote server.properties through `VpsSettingsSync`). `scripts/publish-bridge.ps1` builds all three into `artifacts/bridge/`, which WaNut.App copies into its folder.
- `src/WaNut.App/` WPF + MVVM (CommunityToolkit.Mvvm) + DI. Each tab is `Views/<Tab>View.xaml` + `ViewModels/<Tab>ViewModel.cs` (Players, GameSettings, ServerSettings, Backups, Mods, Packs, Connect, Performance, Files for VPS servers); windows are `Views/*Window.xaml`. `Services/ServerController.cs` runs the servers (several at once, one preparing at a time). UI text: `Resources/Strings.resx` and `Strings.zh-TW.resx` (keys `<Screen>_<Element>`, every key in both). Colors: brush keys from `Themes/` only.
- `tests/WaNut.Core.Tests/` xUnit, one folder per Core module. `tests/FakeMinecraftServer/` fakes server output.
- `.github/workflows/ci.yml` build + test on Windows; `release.yml` runs on `v*` tags.
