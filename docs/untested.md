# 尚未實際驗證的項目

介面的外觀與手感沒有自動測試。這裡列出已合併或送審、但還沒有人在真的視窗上用滑鼠鍵盤確認過的行為。確認過就把那一行刪掉；發現問題就開 issue 或修正後刪掉。

## 美術風格實施（`docs/design-rollout.md`）

### 步驟 2：動效共用資源與控制項回饋

已確認：程式在淺色、深色主題下正常開啟並顯示硬邊底緣；用離屏視窗確認過 hover、核取、清單選取的圖層會在約 100ms 內淡入淡出，動畫關閉時直接切換。

還沒確認：

- 用真的滑鼠移到按鈕、下拉選單、清單項目、「更多設定」標題上時，hover 顏色有淡入淡出。
- 按住按鈕時整顆下移 3px 蓋住底緣，放開後回到原位；鍵盤按 Space、Enter 時也一樣。
- 按鈕比以前高 3px 之後，各畫面沒有被擠壓或文字被切掉的地方（只看過主視窗空白狀態與初次設定視窗）。
- 側欄伺服器列的「啟動／停止」按鈕在執行中變綠色時，hover 與底緣顏色是綠色系。
- 在 Windows「設定 > 協助工具 > 視覺效果」關閉動畫效果後重開 WaNut，所有顏色變化都是瞬間切換。
- 深色主題的一般按鈕底緣（`#14110D`）在深色背景上是否夠明顯。
- 虛線的「建立伺服器」按鈕、下拉選單和文字輸入框沒有底緣是刻意的，要看實際畫面是否協調。

### 步驟 3：間距與字級收斂

所有畫面的 `Margin`／`Padding` 由腳本換成最接近的尺度值（例如 8→6、10→12、14→12、16→18、20→18、22→24、1→0、2→3），字級換成四級（11→12、14→15、20 和 22→21）。已確認：程式能開啟，主視窗空白狀態與初次設定視窗看起來正常。

還沒確認，每個畫面都要打開看一次：

- 八個分頁（玩家、遊戲設定、伺服器、備份、模組、資料包、連線、效能）與主控台：沒有文字被切掉、沒有元素重疊或擠在一起。
- 所有獨立視窗（建立伺服器、App 設定、VPS、模組詳情、變更伺服器、匯入匯出世界、還原、六個確認視窗）：內容沒有超出視窗、按鈕列對齊。
- 原本靠 1–2px 微調對齊的地方（核取方塊與文字、提示文字的縮排、清單列的圖示）現在是否還對齊。
- 主控台行距變緊（每行上下各少 1px）後是否仍好讀。
- 分頁標題從 14 變 15、標題從 20 或 22 變 21 之後，窄視窗下分頁是否會多換一行。
- 分頁列的選取底線原本蓋住下方的分隔線，現在在分隔線上方 1px。
- 鍵盤焦點框從控制項外 2px 變成 3px，是否會被相鄰元素裁掉。
- 分頁裡的內文改回規範的 13（原本跟著分頁標題變成 15），而且選取分頁的半粗體不再傳給分頁裡的所有文字。要確認：八個分頁與主控台的文字變小、變細後仍好讀，原本靠內文半粗體顯眼的地方（例如清單項目名稱）有自己的 `FontWeight`。

### 步驟 4：分頁與內容切換的過場

已確認：用離屏視窗確認過選取指示線會滑到新分頁、滑到一半再切換會從目前位置接著滑、分頁內容淡入；動畫關閉時直接到位。實際程式中指示線出現在選取的分頁下方。

還沒確認：

- 用滑鼠連續快速切換分頁、切換伺服器時不卡、沒有殘影。
- 切換伺服器時，右側整塊內容淡入並上移 6px 的手感。
- 視窗變窄讓分頁換成兩行時，指示線跟著到第二行（設計上跨行時直接跳過去，不滑動）。
- 「玩家（N）」「模組」這類標題文字改變、或分頁出現與消失時，指示線跟著移動。
- 鍵盤用方向鍵切換分頁時指示線也會滑動。

### 步驟 5：狀態與訊息的出現

已確認：用離屏視窗確認過橫幅出現時下方內容是逐步被推開的、進度條往前時滑動而倒退時直接到位；動畫關閉時都是直接切換。實際程式能開啟，狀態徽章在停止狀態下外觀不變。

清單項目的滑入滑出（玩家、備份、已安裝模組）後來補上：ViewModel 改成只增減有變動的項目（`ListSync`，有單元測試），清單用 `behaviors:ListMotion.ItemsSource` 讓新增的列從零高度展開、移除的列收合後才消失。一次變動超過 6 列（例如第一次載入）、清單不在畫面上或動畫關閉時直接切換。只在 Linux 上建置與跑過單元測試，沒有在 Windows 上看過。

還沒確認（清單動畫）：

- 有玩家上線、下線時，「在線上」與「最近來過」兩個清單的列是展開與收合的，旁邊的列平順移動；玩家的頭像不會每次都重新載入閃一下。
- 在白名單、管理員、封鎖清單新增與移除玩家時，只有那一列在動。
- 立刻備份、刪除備份、加入與移除模組時，只有那一列在動；已安裝模組的清單可以捲動，捲到下面時也正常。
- 正在收合的列點不到；在收合途中又把同一位玩家加回來，不會出現兩列。
- 切到別的分頁再切回來時，清單不會整份重新展開。
- 「⋯」選單裡的「設為管理員／取消管理員」等文字，在玩家被加入或移出清單之後是對的（列現在會保留，所以改成跟著更新）。
- 動畫關閉時，清單直接增減。

還沒確認：

- 啟動一台伺服器，從停止到上線的過程中：狀態徽章的底色淡入淡出（停止 → 啟動中的黃 → 上線的綠），文字顏色是瞬間切換的，看起來是否協調。
- 真的出現錯誤、警告、提示橫幅時（例如伺服器開著時進入遊戲設定分頁、當機說明），橫幅是展開的。
- 切換分頁或切換伺服器時，已經在顯示的橫幅不會重新展開一次。
- 橫幅消失時仍是瞬間消失，下方內容會跳上來。
- 下載 Java 或伺服器檔案、備份時進度條平滑前進；切到下一階段歸零時直接跳回。
- 視窗寬度改變時進度條的填滿比例正確。

### 步驟 8：視窗內面板（共用面板與一般確認）

已確認：用離屏視窗確認過「是」回傳是、「否」／Esc／點遮罩回傳否、開啟時焦點在「否」、關閉後焦點回到原本的輸入框、面板開著時視窗關不掉。實際程式套用新的視窗範本後能正常開啟。

還沒確認：

- 實際觸發一次確認（例如移除模組、刪除備份、在伺服器執行中關閉程式的相關詢問），面板出現在主視窗中央，外觀與進場動畫是否合適。
- 在 App 設定、建立伺服器、VPS 這些較小的視窗裡觸發確認時，面板有沒有被視窗邊界切掉。
- 用 Tab 鍵時焦點只在「是」「否」之間循環，不會跑到遮罩下面的控制項。
- 面板開著時按 Enter、Esc 不會觸發下面視窗的預設按鈕或取消按鈕。
- 螢幕閱讀器會唸出問題內容。
- 主視窗縮到工作列或通知區時出現確認：視窗會被還原並顯示面板。
- 所有視窗改用自訂範本後，標題列顏色、視窗縮放、導覽遮罩是否都和以前一樣。

### 步驟 8：關閉時的選擇

已確認：用離屏視窗確認過焦點在核取方塊時按 Enter 會選「留在通知區」並記住勾選、「停止」回傳停止、Esc 回傳取消。

還沒確認：

- 伺服器執行中按主視窗的 X：面板出現在主視窗裡，三個按鈕的結果和以前一樣（縮到通知區、停止後關閉、取消後視窗留著）。
- 面板開著時再按一次 X 不會出現第二個面板，也不會關掉視窗。
- 勾選「記住」後，下次關閉不再詢問。

### 步驟 6：新花生與成功時刻的回彈

已確認：規則測試確認所有像素圖都是 48、72 或 96px；實際程式的側欄標誌是新的 72px 花生、標題區狀態圖是 96px、玩家與備份分頁的空白狀態圖是 96px；用離屏視窗確認過打勾標示出現時會回彈，動畫關閉時不動。

還沒確認：

- 被拿掉小圖的地方看起來是否空了一塊：建立伺服器的類型清單（原本每一列有類型圖示）、各視窗標題旁、匯入匯出與備份的進度文字旁、更新通知卡、玩家分頁的空清單、伺服器分頁的圖示預留位置、過熱警告。
- 打勾標示取代小花生的地方：備份完成、防火牆正常、VPS 可連線、變更版本完成。
- 伺服器上線的那一刻，標題區的狀態圖回彈一次，而且切換到另一台已上線的伺服器時不會再彈。
- 標題區因為狀態圖變成 96px 而變高，小視窗下是否擠壓到分頁內容。
- 導覽泡泡（96px 的圖）、初次設定視窗（72px 花生）、沒有伺服器時的大圖（從 128 變 96px）、效能分頁的圖。
- 啟動中的大花生（72px）仍會左右搖擺。
- 沒有做：長時間工作完成時的回彈只做在有打勾標示的地方（備份完成、變更版本完成）；下載、匯入匯出、模組包安裝完成時沒有對應的畫面元素可以彈。

### 步驟 8：封鎖玩家

已確認：用離屏視窗確認過在原因欄按 Enter 會取消（和原本一樣，取消是預設）、按「封鎖」會帶回去掉頭尾空白的原因。

還沒確認：

- 在玩家分頁實際封鎖一位玩家：面板出現在主視窗裡，標題、原因欄、按鈕排列是否合適。
- 面板沒有標題列了，原本視窗標題的文字改成面板裡的大標題。

### 步驟 8：重置世界

已確認：用離屏視窗確認過填入種子後按「重置」會帶回去掉頭尾空白的種子。

還沒確認：

- 在備份分頁實際按「開新世界」：面板出現在主視窗裡，備份說明的提示框不會讓面板超出視窗高度。
- 在種子欄按 Enter 會取消（取消是預設），Esc 與點遮罩也會取消。

### 步驟 8：刪除伺服器

已確認：程式能建置，共用面板原有的行為（一般確認、關閉時的選擇、封鎖、重置）在修改後用離屏視窗重跑都正常。刪除面板本身沒有用離屏視窗跑過，因為它需要真的伺服器資料。

還沒確認，請用一台測試用的伺服器實際做一次：

- 刪除面板出現在主視窗裡；勾選「保留世界」後刪除，會留下壓縮檔。
- 刪除進行中按「取消」或 Esc：刪除停止、面板留著。
- 刪除進行中點遮罩：刪除停止、面板關閉。
- 沒在刪除時按 Esc、點遮罩、按「取消」：面板關閉，伺服器還在。
- 焦點在核取方塊時按 Enter 等於按「取消」。
- 刪除失敗時錯誤橫幅顯示在面板內，面板不會超出視窗高度。

### 步驟 8：複製伺服器

已確認：程式能建置。複製面板本身沒有用離屏視窗跑過，因為它需要真的伺服器資料。

還沒確認，請實際複製一台伺服器：

- 面板出現在主視窗裡，名稱欄有焦點且建議的名稱整段被選取。
- 在名稱欄按 Enter 等於按「複製」；名稱不合法時按鈕停用，Enter 不會動作。
- 複製進行中按「取消」或 Esc：複製停止、面板留著；點遮罩：複製停止、面板關閉。
- 複製完成後面板關閉，新伺服器出現在清單並被選取。

### 步驟 7：標題圓體

已確認：實際程式的側欄標題與伺服器名稱以昭源環方粗體顯示（淺色主題）。

還沒確認：

- 深色主題下的標題。
- 各視窗與面板的標題（建立伺服器、App 設定、VPS、模組詳情、匯入匯出、還原、刪除、複製、封鎖、重置）與效能分頁的大數字。
- 伺服器名稱含字型沒有的字（罕用字、表情符號、日文假名、韓文）時，會改用系統字顯示而不是方框。
- 內文明確指定微軟正黑體後，全形標點與中英混排的樣子是否和以前一樣可接受。
- 實際打包安裝檔後的大小（下面的數字是未壓縮的增加量）。

### 換回舊花生

改回 v0.4.0 以前的 16×16 斜放花生（沒有臉），一律以 3 倍 48px 顯示；場景圖本來就是舊造型，沒有動。

還沒確認：

- 側欄標誌、初次設定視窗、連線分頁沒有位址時、存檔中的大花生都是舊花生，48px、邊緣銳利，兩個主題下都清楚。
- 側欄標誌從 72px 變 48px 後，和「WaNut」標題的對齊與間距看起來還順。
- 存檔中的花生仍會左右搖擺。

## 載入步驟條（建立、啟動、關閉、備份）

建立伺服器視窗的進度區，以及主視窗分頁上方，在建立、啟動、關閉、備份時顯示「02 / 05 ＋ 步驟標題」、一句說明，和一排用線連起來的圓圈圖示。只靠真實進度前進：建立的階段、Java 下載、啟動時的 log（`Preparing level`、`Preparing spawn area`）、上線、`Stopping server`、`Saving worlds`、`All dimensions are saved`、程式結束、VPS 檔案取回、備份開始壓縮。只在 Linux 上建置與跑 Core 測試，沒有在 Windows 視窗上看過。

還沒確認：

- 圖示字型：Windows 11 用 Segoe Fluent Icons、Windows 10 用 Segoe MDL2 Assets；每個圖示（尤其 Java 的咖啡杯 ``、拼圖 ``）在兩種系統都顯示得出來，不是方框。
- 目前步驟的深色實心圓、走過的深色外框圓、還沒到的灰色圓，在淺色和深色主題下都清楚；連線往前填滿的動畫順。
- 建立視窗固定高 640px，步驟條加在下方後，表單捲動區還夠用；7 個步驟（Forge＋模組包）的標籤不會擠在一起，中文標籤也不會被截斷。
- 建立完成後全部打勾停 0.7 秒才關視窗；這段時間按「取消」或關視窗不會出錯。
- 啟動：沒有世界的第一次啟動（備份直接跳過）會從備份跳到 Java 再到啟動；Paper、Fabric、Forge、NeoForge 和 1.16.5–最新版都會印出 `Preparing level` 或 `Preparing spawn area`，否則「載入世界」這一步會被直接跳過到上線（不會卡住）。
- 啟動失敗或當機時步驟條會收起，只留當機卡片；排隊等其他伺服器準備時，步驟條停在「備份」並顯示等待中。
- 關閉：在遊戲裡打 `/stop`、沒人自動關閉、主控台打 stop 都會出現步驟條；`All dimensions are saved` 在新版改成別的字時，「關閉」這一步會直接跳到「已停止」。
- VPS：連線、Java、上傳各步驟依序前進；停止後「取回」這一步在檔案下載回來並備份後才完成；連線中斷或關閉 WaNut 讓伺服器留在 VPS 時步驟條不會卡在「取回」。
- 備份：「立即備份」與定時備份都顯示；執行中的伺服器先停在「存檔」直到 `Saved the game`，再進「打包」；還原與重置世界不顯示步驟條。完成後停 2 秒自動收起。

## 步驟條可收合（啟動、關閉、備份）

主視窗的步驟條右上多一個箭頭按鈕，按了只留「02 / 05 ＋ 步驟標題」那一行，說明和圓圈收起來；再按展開。選擇存在 config.json（`FoldSteps`），所有伺服器共用，重開 WaNut 也記得。建立伺服器視窗的步驟條沒有這個按鈕。只在 Linux 上建置與跑 Core 測試，沒有在 Windows 視窗上看過。

還沒確認：

- 箭頭按鈕的位置、大小、滑過的底色在淺色和深色主題下看起來對；展開時箭頭朝下、收合時朝右。
- 收合狀態下步驟前進時，編號和標題照常更新；收合後再展開，圓圈和連線停在正確的步驟。
- 在一台伺服器收合後，切到另一台伺服器也是收合的；重開 WaNut 後還是收合。
- 鍵盤 Tab 可以走到按鈕，空白鍵可切換。

## 關服時把檔案留在 VPS（伺服器分頁 > 進階模式）

## Discord 橋接壓力與恢復測試（add-bridge-stress-tests）

只新增測試和修 bug，沒有新功能。測試在 Linux 雲端跑，沒有真的 Discord、Minecraft 或 Windows。

已測（`tests/WaNut.Bridge.Tests/Stress/`，約 100 個測試，加上用發佈檔跑的浸泡）：

- Discord 洪水：假 Webhook 用虛擬時鐘模擬「每 2 秒 5 次，超過回 429 附 `retry_after`」。每次 400 行、輪流 7 個玩家，共 16000 行，一行都沒少、順序不變、有 Bucket 標頭時一次 429 都沒有；沒有標頭時靠 429 重送也全部送達。一次塞 20000 行（超過佇列 500）時保留最新的行、順序不亂。斷網 8 秒內全部補送；斷網超過重試時間（約 30 秒），正在送的那幾則會放棄，之後的訊息照常送出。
- RCON：用真的 TCP 假伺服器反覆停止、重啟五次，連線每次都自己回來；伺服器長時間關著時重試間隔 1、2、4、8、16、32、60、60…；密碼錯只記一次；8 個傳送端同時送指令時伺服器重啟，沒有例外也沒有卡住。
- latest.log：寫入端一邊分兩段寫 10 萬行、讀取端一邊輪詢，一行不少不重複；伺服器重開 20 次（含中間完全沒有檔案的空檔）每個新檔都從第一行讀；copytruncate 式清空重寫；橋接重啟後不會重複轉發舊行；40 MB 沒有換行的超長行不會吃光記憶體；惡意長行解析在 3 秒內完成。
- Gateway：連線失敗 1、2、4…最多 60 秒；中途斷線用最後的序號 Resume 並繼續收訊息；InvalidSession 後重新 Identify；30 次一連上就斷也撐得住；10 種壞封包（不是 JSON、缺欄位、數字溢位、網址壞掉）都不會讓 Gateway 結束；Token 被拒（4004）只停一次不狂連。
- 惡意輸入：引號、反斜線、換行、`§` 色碼（含 `§` 後接 emoji）、單獨的代理字元、`@everyone`、選擇器、控制字元、雙向文字、2 MB 訊息，經過 tellraw 與 Discord 兩條路都是合法 JSON、只有一個 text 值、不會 ping 任何人、符合長度上限；玩家在聊天裡打假的「Alex joined the game」仍然是聊天。
- 發佈檔浸泡（linux-x64，假 Discord 在 443、假 RCON）：每秒 40 行、4 個玩家輪流，持續 150 秒，6000 行全部送到、4 次 429 後自動重送；橋接被 `kill -9` 後重啟沒有重複轉發，但**關著的那段時間寫進 log 的行不會補送**；伺服器換 `latest.log` 後新檔從第一行讀。

修掉的問題（各一個 commit）：RCON 指令排隊時連線關閉會永遠卡住；伺服器重啟後第一則 Discord 訊息會被舊連線吃掉；Discord 聊天進遊戲時等 RCON（最久 10 秒），這段時間 Gateway 讀不到心跳回應而被當成斷線；Gateway 遇到沒預料到的例外會讓整個 Discord 到遊戲方向永久停掉；一行超長的 log 沒有上限；洪水時每位玩家一次請求導致大量遺失，改成洪水時跨玩家合併；長時間洪水時常駐記憶體從 4 MB 一路漲到 40 MB（垃圾沒回收），改成每 15 秒收一次。

實測記憶體（linux-x64 發佈檔，Release、非 NativeAOT）：閒置 RSS 27 MB（共用程式檔 12 MB、私有約 4 MB）；每秒 40 行持續洪水 120 秒，RSS 44 到 47 MB，私有約 12 到 15 MB，CPU 約 2 秒（120 秒內）。修之前同樣的 150 秒洪水 RSS 漲到 72 MB（私有 40 MB），不是洩漏（把 GC 堆上限設成 32 MB 照樣跑完），是垃圾沒收。託管堆沒有直接量，目標「託管記憶體 30 MB 以下」從私有記憶體與堆上限測試推斷成立，但沒有逐項量到。

還沒測，需要真的環境：

- 真的 Discord：Webhook 與 Bot 的真實 429 與 `X-RateLimit-*` 標頭行為、Webhook 名稱限制（含 `discord`、`clyde`、長度）、Gateway 的 Hello／Resume／4004／4014 真實行為，以及 Discord 側 10 分鐘 Resume 視窗過期後的 InvalidSession。
- 真的 Minecraft：Paper、Fabric、Forge 的 `latest.log` 換檔方式（改名、壓縮成 gz）、RCON 對超長指令與非 ASCII 的實際反應、tellraw 在 1.16.5 到最新版對 `\uXXXX` 的處理。

- 橋接重啟時關著那段時間的 log 不補送，是目前的設計（啟動時從檔尾開始）。要補送得記住讀到哪裡，需要 Peanut 決定。

## Discord Rich Presence（add-discord-rich-presence）

App 設定的 Discord 區塊新增勾選「在我的 Discord 個人檔案顯示執行中的伺服器」（預設關）。打開後 WaNut 每 15 秒看一次有沒有上線的伺服器（本機或 VPS，選在線人數最多的一台），在 Discord 個人檔案顯示：第一行伺服器名稱，第二行「類型 版本 · N 人在線」（VPS 加「在 VPS 上」），經過時間，一個按鈕連到 WaNut 的 GitHub。不顯示 IP。自己寫的 Discord IPC 用戶端（named pipe `discord-ipc-0` 到 `-9`，握手加 SET_ACTIVITY），Discord 沒開時靜默重試，不影響伺服器。Application ID 寫在 `PresenceService.ApplicationId`。已有單元測試（框架、握手、斷線重連）；還沒對真的 Discord 測過。要實測：
- 開著 Discord 桌面版，勾選後啟動一台伺服器，約 15 秒內個人檔案出現「正在玩 WaNut」、名稱、版本與人數；有人進出後更新；停止伺服器後消失；取消勾選也會消失。
- 先啟動伺服器再開 Discord，Discord 開起來後 15 秒內出現。
- VPS 伺服器顯示「在 VPS 上」。按鈕在別人看你的檔案時才看得到（自己看不到是正常的）。
## Discord 崩潰警報與遠端指令稽核（add-discord-crash-alerts）

橋接看到崩潰訊號（crash report 已存檔、server tick loop 例外、連接埠綁不上、Fabric 不相容 mod、OutOfMemoryError 等）後等 3 秒，用 WaNut 既有的崩潰分析讀最後 300 行與 crash-reports 裡最新的報告，在頻道發一則警報：原因加一個建議做法（中英文依 `language`）；5 分鐘內重複的崩潰訊號不再發，避免重啟迴圈洗版；「伺服器開關機通知」關掉時也不發。`/cmd` 的使用與被拒絕的嘗試都寫進 bridge.log（含 Discord 使用者名稱與 id，被拒絕的是 WARN）。已有單元測試；沒有接真的伺服器與 Discord。要實測：
- 本機與 VPS 各一台：故意讓連接埠被占用或給太小的記憶體，Discord 收到警報，原因與建議合理；連續重啟只收到一則。
- 非管理員用 `/cmd`：bridge.log（VPS 用 journalctl）有 `Remote console denied` 一行。

## Discord 狀態看板（add-discord-status-board）

Discord 分頁新增勾選「在頻道放一則會自動更新的狀態訊息」（預設關，需要機器人，只有 Webhook 不行）。橋接每 60 秒編輯同一則訊息：狀態、玩家人數與名單、TPS（Paper 用 `tps`，Vanilla 1.20.3+ 用 `tick query`，兩者都沒有就不顯示）、MSPT、運行時間（橋接在伺服器開完才啟動時，沒有運行時間）。訊息 id 存在 bridge.config.json 旁的 status-board.id，重啟後繼續編輯同一則；訊息被刪掉就重發。記憶體與 CPU 沒做（橋接只透過 RCON 與日誌，取不到 Java 進程）。已有單元測試；沒有接真的伺服器與 Discord。要實測：
- Paper 與 Vanilla 1.21 各開一台，勾選後頻道出現一則狀態訊息，一分鐘內數字更新；關掉伺服器後變成「未開啟」；刪掉那則訊息後下一輪重發。
- 重啟橋接後編輯的是同一則訊息，沒有多一則。

## 伺服器設定資料模型 Phase 1（add-data-driven-server-config）

只新增 Core 的資料模型（`Settings/Config/`），還沒有任何畫面使用它，所以沒有可點的行為。還沒確認：

- 用真實的模組服 `server.properties`（含自訂 key 和註解）載入、改一個值、存檔後，自訂 key、註解與順序都還在（單元測試只用手寫的樣本）。
- 目錄（`ServerConfigCatalog`）的預設值與範圍和各版本真實伺服器一致，尤其 1.21.9 之後 `pvp`、`enable-command-block`、`spawn-monsters` 改成遊戲規則的版本，以及 `pause-when-empty-seconds` 等新 key。

## 設定頁三層介面與搜尋 Phase 2（add-three-layer-settings-page）

遊戲設定分頁改成用 `ServerConfig` 產生：核心設定（遊戲模式、難度、最多玩家數、正版驗證、PvP、死亡不掉落、伺服器訊息）永遠展開；「世界與規則」「連線與效能」兩個可收合群組取代原本「更多設定」的圖形部分；最上面一個搜尋框（比對中文名稱、英文名稱、說明與檔案 key，有符合的群組自動展開，清空後還原）；進階模式多一個「全部設定項目」，列出 `server.properties` 每一行（含模組加的），和上面的圖形控制項是同一份值。死亡不掉落等遊戲規則走原本的路徑（存 instance.json、伺服器上線時送 `gamerule`）。還沒有警告橫幅、修改圓點與重設（Phase 3），伺服器分頁原本的連接埠與正版驗證也還在。只在 Linux 建置與跑 Core 單元測試，沒有在 Windows 開過畫面。要實測：
- 開遊戲設定分頁：核心七項展開、兩個群組收合；改遊戲模式、最多玩家數、motd，開 `server.properties` 看只有那幾行變了，註解與其他 key 都在。
- 伺服器執行中：灰色項目不能改，死亡不掉落、（1.21.9 以上）PvP、指令方塊、生成怪物可以改，主控台看到 `gamerule` 回應；1.21.1 與 1.21.11 各試一次，指令名稱（`keepInventory` / `keep_inventory`）要對。
- 搜尋：輸入「飛」、「flight」、「allow-flight」、「視野」、「rcon」都找得到對應項目；有符合的群組自動展開，沒有符合的群組消失，清空後回到搜尋前展開或收合的狀態；完全沒有符合時出現「找不到符合的設定」。
- 進階模式開關：只有開啟時才出現「全部設定項目」；在那裡改一個值，上面的圖形控制項立刻跟著變，反過來也一樣；模組加的 key 看得到、改得動。進階模式的 JVM 參數等其他項目沒動。
- 世界已存在時種子碼唯讀並顯示說明；VPS 檔案留在 VPS 時改設定仍會推回 VPS。
- 在遊戲設定改連接埠或正版驗證後切到伺服器分頁，看到的是新值（切換分頁時會重新讀檔），反過來也一樣。
- 深色模式、鍵盤操作（Tab 順序、搜尋框）、螢幕閱讀器朗讀名稱；Windows 關閉動畫效果時沒有任何動畫（群組展開本來就是直接切換）。

## 設定頁警告、修改圓點與重設 Phase 3（add-settings-warnings-and-reset）

遊戲設定每一列多了「和預設值不同」的小圓點與還原預設值的按鈕（進階模式的完整清單也有）；正版驗證關閉時，那一列下方展開紅色橫幅（沒有對話框）；視野距離或模擬距離超過 12 時展開一則中性的提醒。伺服器分頁原本重複的連接埠與正版驗證已移除，只剩遊戲設定分頁有。只在 Linux 建置與跑 Core 單元測試，沒有在 Windows 開過畫面。要實測：
- 把正版驗證關掉：紅色橫幅在該列下方展開，寫著帳號冒用、管理員被接管的風險並建議登入外掛；再打開，橫幅收起；中文、英文各看一次，深色模式下紅底文字夠清楚。
- 把視野距離拉到 13 以上：出現提醒，拉回 12 以下收起；模擬距離同理；新建的伺服器（預設都是 10）一開始沒有任何提醒。拖滑桿時滑桿寬度不會跳動。
- 改任何一項：該列出現圓點與還原按鈕（滑鼠移上去有提示），按下去值回到預設、圓點消失，`server.properties` 對應那行也變回預設；遊戲規則項目（死亡不掉落、PvP）還原後伺服器上線時會送 `gamerule`。
- 伺服器執行中或種子碼鎖住時，還原按鈕是灰的；Tab 鍵可以走到還原按鈕、焦點框看得到，螢幕閱讀器念出「還原預設值」。
- 進階模式的完整清單：模組加的 key 沒有圓點與還原按鈕；目錄內的 key 有。
- Windows 關閉動畫效果後，橫幅與提醒是直接出現，沒有展開動畫。
- 伺服器分頁「更多設定」裡不再有連接埠與正版驗證；改遊戲設定的連接埠後，連線分頁顯示的位址是新值。
